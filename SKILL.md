# Skill — add-etl-feature

- **Когда подгружать:** задача добавляет новую стадию/выгрузку, новый CLI-аргумент или новый подмодуль. Глобальные правила — в `AGENTS.md`.

## Architecture & Code Conventions (Конвенции проекта)
1. **Синхронизация публичного API пакетов:** При добавлении новых функций или стадий в подмодули (например, в `pipeline/`), не забывайте обновлять `__all__` в соответствующих `__init__.py` файлах.
2. **Совместимость дефолтов CLI:** В argparse для add_argument использовать статические литералы (например, default=3_000_000), чтобы парсер аргументов проходил статический анализ структуры, а логику перекрытия через ERARTA_* переменные реализовывать внутри функции-обработчика.

---

## Documentation & Fixtures Requirements
- **Фикстуры для данных:** Для каждой новой выгрузки создавайте эталонную фикстуру `tests/*.json` и обеспечивайте её сверку с БД в режиме read-only.

## Чек-лист: добавление новой стадии/выгрузки
1. **Модуль:** стадия (сбор/обход) — функция `run_<stage>` в модуль `erarta_scraper/pipeline/<stage>.py`; выгрузка (агрегированный отчёт) — функция в `erarta_scraper/analytics.py`. Запросы и в том, и в другом случае — через `db/repositories`, без SQL напрямую; агрегации — с фильтром `status == DONE` (AGENTS.md, «Сырой SQL в Pipeline», «Обязательная фильтрация статусов»).
2. **CLI:** зарегистрировать в `--stage choices` и добавить ветку диспетчеризации в `main()` файла `erarta_scraper/cli.py`: стадия вызывает `run_<stage>` из `pipeline/`, выгрузка — напрямую из `analytics.py` (как `collect`/`visit`).
3. **Аргумент и env:** новый `add_argument` — со статическим литералом `default` (`None`/число/строка/bool — как в существующих аргументах; `default=Name` не допускается); перекрытие через `ERARTA_*` — внутри `settings_from_args` (п. 2 раздела Architecture выше); новая переменная окружения — строго с префиксом `ERARTA_` в `erarta_scraper/config.py`.
4. **API пакета:** для стадии в `pipeline/` — добавить `run_<stage>` в `__all__` модуля `erarta_scraper/pipeline/__init__.py` (п. 1 раздела Architecture выше).
5. **Фикстура и тест:** для новой выгрузки — эталонная фикстура `tests/*.json` со сверкой с БД read-only; новый тест в `tests/` (имя по стадии или модулю).
6. **Ритуал:** pytest и smoke `python main.py --help` (AGENTS.md, «Ритуал проверки»).
