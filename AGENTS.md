# AGENTS.md — Erarta ETL Pipeline

## Core Rules & Constraints
- **Необходимость проверки:** После ЛЮБОЙ правки обязательно запускать: pytest и smoke-проверку CLI (python main.py --help).
- **Минимальные изменения:** Изменяй только то, что нужно для задачи. Никакого лишнего рефакторинга.
- **Работа в нужном модуле:** Четко разделяй зоны ответственности слоев.
- **Без домыслей:** Если данных не хватает, остановись и спроси. Не придумывай логику сам.
- **Работа в ветке:** Запрещено коммитить напрямую в `main` — работай только в отдельной ветке.

## NOT to do 
- **Print в библиотечном коде:** В `erarta_scraper/` запрещено использовать `print()`. Используйте только логгер `erarta`. *(Исключение: корневые точки входа типа `main.py` или `link_*.py`, там можно).*
- **Неправильный логгер:** Нельзя создавать логгеры с любым именем, кроме `erarta`.
- **Env без префикса:** Все переменные окружения должны идти строго с префиксом `ERARTA_` (`ERARTA_PAGES`, `ERARTA_DB_PATH` и т.д.).
- **Прямой Selenium:** Запрещено вызывать Selenium напрямую в `pipeline/`, `cli/` или `db/`. Взаимодействие с браузером идет только через `scraping.BrowserSession`.
- **SQL в CLI:** Запрещено писать логику SQL или агрегации данных в `cli.py`.
- **Сырой SQL в Pipeline:** Запрещено писать SQL-запросы, агрегации (select, func.sum, group_by, having) напрямую в слое pipeline/. Оркестрация не должна ходить в БД напрямую — всю логику запросов выносите в db/repositories; `analytics.py` из `pipeline/` не импортируется — аналитика вызывается из `cli`.
- **Импорт cli:** `erarta_scraper.cli` импортируется только из `main.py`; остальные модули (в т.ч. `pipeline/`, корневые `link_*.py`) не подключают CLI.
- **Импорты в domain:** Запрещено делать импорты в слое domain/ из scraping/, db/, pipeline/ или cli/ (чистый домен зависит только от exceptions).
- **Коммит артефактов:** Не коммитите сгенерированные файлы (`top_artists.json`, `*.db` — они в `.gitignore`). При этом фикстуры `tests/*.json` коммитить **обязательно** (! исключение в гитигноре).
- **Нарушение robots.txt / лимитов:** Запрещено «давить» живой сайт. Используйте встроенный `Pace`-лимитер, проект учебный.

## Architecture & Code Conventions (Конвенции проекта)
1. **Очередь в БД:** Новые карточки всегда `ArtworkStatus.PENDING`; воркер меняет на `DONE` или `ERROR`. Не хранить состояние в памяти.
2. **Идемпотентный enqueue:** `ArtworkRepository.enqueue_urls` делает `ON CONFLICT DO NOTHING` по `url` и не сбрасывает статус обработанных строк.
3. **Get-or-create с кэшем:** `ArtistRepository.get_or_create_id` проверяет in-memory кэш, затем БД, затем `flush()`.
4. **Батч-коммит:** Транзакции фиксятся целиком на пачку, а не на каждую картину.
5. **Иерархия ошибок:** `ScraperError` → `ParseError` / `BrowserError` / `QueueError`. Retry только на сетевые/браузерные сбои.
6. **Локаторы отдельно:** XPath/CSS живут в `scraping/selectors.py`; `details_from_text_getter` принимает любой `locator → text`.
7. **Пауза между запросами:** `Pace` в `BrowserSession.get`.
8. **Обязательная фильтрация статусов:** При выборке и агрегации данных по картинам (например, в аналитике или экспорте) обязательно фильтруйте записи по `status == ArtworkStatus.DONE`, чтобы сохранять единую семантику со всеми модулями.

## Naming & Aliasing Conventions
- **Конфликты имён в корне:** Учитывайте разделение между корневыми файлами (`models.py`, `link_*.py`) и модулями пакета `erarta_scraper/` (`erarta_scraper/db/models.py`). Не допускайте пересечения имён при импортах.
- **Алиасы сессий и БД:** Соблюдайте контекстные соглашения для контекст-менеджеров: используйте `as db` в пайплайнах (collect/visit), но `as session` в тестах и функциях экспорта в соответствии с окружением.
- **Параметры CLI vs Внутренние переменные:** Контролируйте маппинг лексики между интерфейсом и кодом (например, CLI-аргументы `--limit` и `--pages` прокидываются во внутренние параметры вроде `max_total` и `pages_count`).
- **Единообразие логгеров:** Используйте строго `erarta` для инициализации логирования во всех модулях пакета.
